This specification defines the [^agecheck^] element. The element lets a site ask one question: is the person at least a given age? The person decides whether to answer, and the site learns only the result.

This is an early draft. The explainer describes the goals, the open risks, and the open questions. Nothing in this draft is implemented in a shipping browser.

Introduction

Sites that check age today use a button, send people to a third-party service, or ask for an ID. The [^agecheck^] element gives the site a form control instead. The browser asks the person before it shares anything, and the site gets a yes or an error.

The answer is declared, not verified. The explainer explains why this is still useful and where it falls short.

Goals

  • A site learns whether a person meets each age it names. The site gets no birthdate, no name, and no ID, and the answer does not say how the age was set. A site that asks again and again can learn a little more; see Age source and prompt requirements.
  • A site can't use the answer to track people across sites, except by matching the day the answer changes; see Age source and prompt requirements.
  • A user finds it as easy to use as today's "I'm over 18" button.
  • A site adds one element. The site doesn't need an age-check service.
  • The person doesn't need a government ID.
  • It works only on secure pages and only in the top-level page, in regular and private browsing alike.
  • Users using a screen reader or a keyboard can use the <agecheck> element and the browser's prompt.
  • The element works without JavaScript.

Non-goals

  • Not an identity system. Sites that need a name or a birthdate should use the Digital Credentials API.
  • Not a way to sign in. Sites still use passkeys or passwords to recognize people who come back.
