Age source and prompt requirements

The supported ages are 13, 16 and 18.

Age check results

An age check result is one of the following:

meets
The age source says the person is at least the age asked about.
does not meet
The age source gave an age, and that age does not show the person is at least the age asked about.
no age set
The age source has no age for the person.
declined
The person declined inside the platform's own age prompt.
failed
The age source refused to share, could not be reached, or failed for any other reason.

Platform age services

A platform age service is a service of the operating system or device platform that tells applications an age a person declared, an age a parent set, or an age the platform checked. How the platform sets the age is up to the platform.

A [=platform age service=] gives an age range. An [=age range=] has a lower bound, which is either an age or none. A lower bound of none means the range has no bottom, as for a person under 13.

The user agent MUST NOT tell the [=platform age service=] which site asked. The result the user agent gives the page MUST NOT carry any identifier from the platform.

For children, the platform's parental controls decide whether the user agent gets an age at all. The user agent MUST follow those controls, including a parent's choice that the child is asked each time.

Result for an age range

To get the result for an age range given an [=age range=] |range| and an age |age|:

  1. If |range|'s [=age range/lower bound=] is none, return [=age check result/does not meet=].
  2. If |range|'s [=age range/lower bound=] is greater than or equal to |age|, return [=age check result/meets=].
  3. Return [=age check result/does not meet=].

The kept copy of a platform answer

Some platform age services have an anniversary rule: a higher range appears only on the anniversary of the day the age was set.

A kept copy holds an [=age range=] and the date the user agent stored the range. The user agent uses the same [=kept copy=] for every site. The length of time before a higher range applies is user agent specific, for example one year.

To update the kept copy given an [=age range=] |range| from the platform:

  1. If there is no [=kept copy=], store |range| and today's date as the [=kept copy=], then return |range|.
  2. If |range| is lower than the [=kept copy=]'s range, replace the [=kept copy=] with |range| and today's date, then return |range|.
  3. If |range| is higher than the [=kept copy=]'s range and the user agent specific time has passed since the [=kept copy=]'s date, replace the [=kept copy=] with |range| and today's date, then return |range|.
  4. Return the [=kept copy=]'s range.

One range is lower than another when the first range's [=age range/lower bound=] is smaller. A lower bound of none is smaller than every age.

An age group the user agent stores

When the platform offers no [=platform age service=], the user agent MAY offer to store an age the person enters. The user agent stores this age the way the user agent stores payment details for autofill.

A stored age group holds one of four age groups and the date the person entered the group. The age groups are under 13, 13 to 15, 16 to 17, and 18 and over. Each group gives an [=age range=] whose [=age range/lower bound=] is none, 13, 16 or 18, in that order.

  • The user agent SHOULD NOT store a birth date.
  • After a user agent specific time, for example one year, the user agent SHOULD treat the [=stored age group=] as absent, so the person enters an age group again. The user agent SHOULD NOT do so when the stored group is 18 and over.
  • The user agent MUST let the person change the [=stored age group=].
  • A private browsing window MAY read a [=stored age group=] that regular browsing stored. The user agent MUST discard any [=stored age group=] that a private browsing window stored once that private browsing session ends.

Asking the age source

To ask the age source given an age |age| from the [=supported ages=] and a {{Document}} |document|, the user agent runs these steps. The steps return an [=age check result=].

  1. Let |behavior| be the result of [=get the virtual age source behavior=] for |document|, or null if the user agent does not support automated testing. If |behavior| is not null:
    1. While |behavior| is not null and its action is "wait", wait until the test sets another behavior for |document|'s top-level traversable, then set |behavior| to the result of [=get the virtual age source behavior=] for |document|.
    2. If |behavior| is not null, return the result that |behavior|'s action names in [[[#testing-types]]].
  2. If the platform offers a [=platform age service=]:
    1. If the user agent cannot call the [=platform age service=], return [=age check result/failed=].
    2. Ask the [=platform age service=] for the person's [=age range=]. Pass all of the [=supported ages=], not only |age|. Let the platform show its own prompt if the platform chooses. Wait for the answer.
    3. If the person declined in the platform's prompt, return [=age check result/declined=].
    4. If the platform reports that the platform has no age for the person, return [=age check result/no age set=].
    5. If the platform refused to share, discard the [=kept copy=] if there is one, and return [=age check result/failed=]. A platform that returns no [=age range=] counts as refusing to share.
    6. If the platform failed for any other reason, such as a network problem, return [=age check result/failed=].
    7. Let |range:age range| be the [=age range=] the platform gave.
    8. If the [=platform age service=] has no [=anniversary rule=], set |range| to the result of [=update the kept copy=] given |range|.
    9. Return the [=result for an age range=] given |range| and |age|.
  3. If there is no [=stored age group=], return [=age check result/no age set=].
  4. Return the [=result for an age range=] given the [=stored age group=]'s range and |age|.

Remembered consent

Remembered consent is a record that the person agreed to share that the person is at least a given age with a given [=site=]. The user agent keys each record by the [=site=] of the top-level document's [=origin=] and by the age. A record for one age says nothing about any other age.

  • The user agent creates a record when the person agrees in the user agent's prompt.
  • The user agent MUST clear the records for a [=site=] whenever the user agent clears the data the user agent stores for that [=site=].
  • The user agent SHOULD offer a control that clears every record at once.
  • A private browsing window starts with no records and MUST NOT read the records of regular browsing. The user agent MUST discard the records a private browsing window made once that private browsing session ends.
  • The list of sites that asked about age is sensitive. The user agent SHOULD NOT show the person a list of those sites. See [[[#sp-people-in-danger]]].

Prompt requirements

The prompt requirements are the outcomes the user agent's prompt must achieve. This specification does not say how the prompt looks, what the prompt's controls say, or where those controls go.

  1. The prompt MUST name the [=origin=] of the top-level document that started the check.
  2. The person MUST NOT be able to use the page until the person answers or closes the prompt.
  3. The prompt MUST ignore input for a short time after the prompt appears, for example as long as the system's double-click time. A page then cannot use a fast second click to answer a prompt the person has not seen yet.
  4. The prompt MUST ignore input while a window from the page or from another application covers the prompt. A window that the person's assistive technology draws, such as an on-screen keyboard or a magnifier, does not count as covering the prompt.
  5. A key that the person was already holding down when the prompt appeared MUST NOT answer the prompt.
  6. The page MUST NOT be able to learn the person's choice from traces the prompt leaves, such as where the pointer rests, which element has focus afterward, or how long the user agent took.
  7. The prompt MUST NOT ask the person to share an age the person does not meet. When the result is not [=age check result/meets=], the prompt tells the person that the age cannot be shared, and the person can only close the prompt.
  8. When the user agent offers a [=stored age group=] and has none, the prompt MAY let the person choose an age group. The user agent then stores that group. The check then goes on with the [=result for an age range=] given that group's range and the age asked about. If the person chooses no group, the check fails.
  9. The user agent MUST NOT add a timing difference of its own between failures. So the page cannot tell a person who is too young from a person who has no age set, declined, or hit an age source failure.
