Running a check

State for a check

Each agecheck element has a check pending boolean, initially false. The boolean is true while a check from the element is running.

Each {{Document}} has a check in progress boolean, initially false. The boolean makes sure that a document runs only one check at a time.

The run a check algorithm

The activation behavior of an agecheck element calls these steps only after it has checked that the event is trusted. To run a check given an agecheck element |element|:

  1. If |element| is disabled, then return.
  2. If |element|'s meets age flag is true, then return.
  3. If |element|'s [=agecheck/check pending=] is true, then return.
  4. Let |document| be |element|'s node document.
  5. If |document|'s [=Document/check in progress=] is true, then [=queue an element task=] on the [=user interaction task source=] given |element| to [=agecheck/report a check failure=] given |element| and "Another age check is already running in this document.", and return.
  6. If |document|'s [=node navigable=] is null, or is not a [=top-level traversable=], then [=queue an element task=] on the [=user interaction task source=] given |element| to [=agecheck/report a check failure=] given |element| and "An age check works only in a top-level document.", and return.
  7. If |element|'s [=relevant settings object=] is not a [=secure context=], then [=queue an element task=] on the [=user interaction task source=] given |element| to [=agecheck/report a check failure=] given |element| and "An age check works only in a secure context.", and return.
  8. If |document|'s active sandboxing flag set has the sandboxed modals flag, then [=queue an element task=] on the [=user interaction task source=] given |element| to [=agecheck/report a check failure=] given |element| and "An age check does not work in a sandboxed document that blocks modal dialogs.", and return.
  9. If |document|'s [=Document/origin=] is an opaque origin, then [=queue an element task=] on the [=user interaction task source=] given |element| to [=agecheck/report a check failure=] given |element| and "An age check needs a document whose site the prompt can name.", and return.
  10. Let |age| be the [=agecheck/requested age=] of |element|.
  11. If |age| is failure, then [=queue an element task=] on the [=user interaction task source=] given |element| to [=agecheck/report a check failure=] given |element| and "The age attribute must be 13, 16, or 18.", and return.
  12. If |element|'s relevant global object does not have transient activation, then [=queue an element task=] on the [=user interaction task source=] given |element| to [=agecheck/report a check failure=] given |element| and "An age check needs a click, a tap, or a key press from the person.", and return.
  13. Consume user activation of |element|'s relevant global object.
  14. Set |element|'s [=agecheck/check pending=] to true.
  15. Set |element|'s [=agecheck/check dropped=] to false.
  16. Set |document|'s [=Document/check in progress=] to true.
  17. Run these steps [=in parallel=]:
    1. Let |result| be the result of running ask the age source given |age| and |document|. The |result| is one of "meets", "does not meet", "no age set", "declined", or "failed".
    2. If |result| is "declined", then [=queue an element task=] on the [=user interaction task source=] given |element| to [=agecheck/finish a check=] given |element|, |age|, false, and |document|, and abort these steps.
    3. Let |shared| be false.
    4. If |result| is "meets" and the user agent holds remembered consent for |document|'s site and |age|, then set |shared| to true.
    5. Otherwise, if |document| is fully active, show a prompt that meets the prompt requirements for |result| and |age|, and wait for the person to answer or close the prompt. If |document| is not fully active, the user agent MUST NOT show the prompt. Closing the prompt without agreeing leaves |shared| false. If |result| is "meets" and the person agrees to share that they are at least |age|, then set |shared| to true.
    6. [=queue an element task=] on the [=user interaction task source=] given |element| to [=agecheck/finish a check=] given |element|, |age|, |shared|, and |document|.

Steps 1 to 3 return without firing an event. So a click that does not start a check fires no event.

Finishing a check

To finish a check given an agecheck element |element|, an integer |age|, a boolean |shared|, and a {{Document}} |document|, where |document| is the document in which the check started:

  1. Set |element|'s [=agecheck/check pending=] to false.
  2. Set |document|'s [=Document/check in progress=] to false.
  3. If |element| is not [=connected=], or |element|'s node document is not |document|, or |document| is not fully active, then [=agecheck/report a check failure=] given |element| and "The agecheck element left the document where the check started, or that document stopped being active, during the check.", and return.
  4. If |element|'s [=agecheck/check dropped=] is true, then [=agecheck/report a check failure=] given |element| and "The check was dropped because the form was reset or the document unloaded.", and return.
  5. Let |currentAge| be the [=agecheck/requested age=] of |element|.
  6. If |currentAge| is not |age|, then [=agecheck/report a check failure=] given |element| and "The age attribute changed during the check.", and return.
  7. If |element| is disabled, then [=agecheck/report a check failure=] given |element| and "The agecheck element was disabled during the check.", and return.
  8. If |shared| is false, then [=fire an event=] named error at |element|, and return.
  9. Set |element|'s meets age flag to true.
  10. [=Fire an event=] named change at |element|, with the {{Event/bubbles}} attribute initialized to true.

To report a check failure given an agecheck element |element| and a string |message|:

  1. The user agent SHOULD report a warning to the console with |message|. The exact text is up to the user agent.
  2. [=Fire an event=] named error at |element|.

When the person answers a prompt after the check was dropped, the user agent drops the answer. The [=agecheck/finish a check=] steps then fire error, even when the person agreed.

Events

Both events use the {{Event}} interface. The change event bubbles. The error event does not bubble, so a failed check never reaches {{Window}} error handlers and never looks like a script error. Neither event is cancelable.

The user agent never fires these events during the activation behavior. The user agent always fires them in a queued task. Every check that gets past step 3 of [=agecheck/run a check=] ends with exactly one event at the element: one change or one error. The element fires no other event for a check. While [=agecheck/check pending=] is true, a new activation of the same element fires no event.

Every failure fires the same error event, with no detail attached. The page cannot tell a person who declined from a person who does not meet the age, has no age set, or whose platform failed. Console messages appear only for failures that the page itself can cause, and scripts cannot read the console.

A "declined" result from the age source fires error at once. The user agent does not show a second prompt after the person declines in the platform's own prompt.

Keeping the element alive

While an element's [=agecheck/check pending=] is true, the user agent MUST NOT garbage collect the element, even when no script holds a reference to the element. The [=agecheck/finish a check=] steps then run and fire their event at the element. Without this rule, the steps might never run, the document's [=Document/check in progress=] flag would stay true, and no later check in the document could start. The rule also keeps the element's event listeners alive until the event fires.

A task is runnable only when its document is fully active. If the document stops being fully active during a check, the queued task waits. If the document becomes fully active again, the task runs and fires error, because the reset on restore sets [=agecheck/check dropped=] to true. See [[[#forms-bfcache]]].
