The agecheck element represents a control labeled by its contents. A person uses the control to share that they are at least the age that the [^agecheck/age^] attribute names. The element uses the HTMLAgeCheckElement interface.

The answer is an age that the person, a parent, or the platform declared. The element does not prove anyone's age. Anyone can send the same form value to a server.

The agecheck element is not a button in the HTML sense. So the element is never a submit button, and activating the element never submits or resets a form.

The element is a resettable element because a form reset must clear the result of an earlier check. HTML runs the reset algorithm only for resettable elements. The reset algorithm for agecheck says what a reset does.

The age attribute

The age content attribute gives the age that a check asks about. If the attribute is present, its value must be a valid non-negative integer equal to 13, 16, or 18.

The attribute's missing value default is 18, so an element with no age attribute asks whether the person is 18 or older. The attribute has no invalid value default. A value that does not parse to 13, 16, or 18 makes the check fail, so a site never gets an answer for an age it did not name. An empty value is an invalid value, not a missing one.

To parse an age given a string or null value:

  1. If value is null, then return 18.
  2. Let number be the result of parsing value with the rules for parsing non-negative integers.
  3. If number is an error, then return failure.
  4. If number is 13, 16, or 18, then return number.
  5. Return failure.

The requested age of an agecheck element is the result of running [=agecheck/parse an age=] on the element's [^agecheck/age^] attribute value. When the element has no age attribute, [=agecheck/parse an age=] gets null instead.

When the requested age is failure, a check fires error and reports the reason to the developer console. See run a check.

The [=attribute change steps=] for an agecheck element element, given localName, oldValue, value, and namespace, are:

  1. If localName is not age or namespace is not null, then return.
  2. Let oldAge be the result of [=agecheck/parse an age=] given oldValue.
  3. Let newAge be the result of [=agecheck/parse an age=] given value.
  4. If oldAge and newAge are both failure, or are the same number, then return.
  5. Set element's [=agecheck/meets age=] flag to false.

A change from "18" to "018" keeps the result, because both strings parse to the same number. Adding age="18" to an element with no age attribute also keeps the result, because both ask about 18.

The name, form, disabled, and required attributes

Authors use the form attribute to associate the agecheck element with its form owner. The name attribute represents the element's name. Authors use the disabled attribute to make the control non-interactive and to keep its value out of form submission. The changes to HTML add agecheck to the lists of elements that HTML's disabled definition names.

The required attribute is a boolean attribute. When the attribute is specified, the element is required.

Constraint validation: If the element is required and the element's [=agecheck/meets age=] flag is false, then the element is suffering from being missing. A disabled element is already barred from constraint validation.

So a required agecheck element blocks form submission until a check succeeds. A form whose author set novalidate still submits.

The meetsAge attribute

Each agecheck element has a meets age flag, a boolean. The flag is initially false. Only a successful check sets the flag to true. See run a check.

The meetsAge getter steps are to return [=this=]'s [=agecheck/meets age=] flag.

A new element starts with the flag set to false. HTML's cloning steps do not copy the flag, so a clone also starts at false. A form reset and a change to age set the flag back to false.

Activation behavior

An agecheck element element's activation behavior given event is:

  1. If element is disabled, then return.
  2. If element's node document is not fully active, then return.
  3. If event's {{Event/isTrusted}} attribute is false, then return.
  4. Run a check given element.

DOM runs an element's activation behavior when a click event is dispatched at the element.

Script can call click() or dispatchEvent(). Both create an event whose {{Event/isTrusted}} attribute is false. So script cannot start a check, even while the person is clicking on something else.

These steps ask for a trusted event. Run a check also needs transient activation and consumes it. So one click or key press starts at most one check, and a page that already spent the activation on something else, such as opening a popup, gets error.

What counts as activating the element

The user agent must fire a click event at an agecheck element, with {{Event/isTrusted}} set to true, in each of these cases:

  • The person clicks or taps the element.
  • The element has focus and the person presses the Enter key, or presses and then releases the Space key. For the button role, these are the same keys that activate a button element on the same platform.
  • The person's assistive technology asks for the element's press action, or the platform's equivalent default action. Before the user agent fires the click event, it MUST give the element's relevant global object transient activation, as it does for an activation triggering input event.
The rule in the last item patches HTML's user activation processing model, which has no notion of an assistive technology press action. The rule sits here for now. It moves into HTML with the other patches.

HTML lets each platform decide what a click on a label element does. For an agecheck element that is a label's labeled control, the label patch in sets one fixed rule: a trusted click on the label fires a trusted click at the element.

So a person's own click on the label can start a check. A label click that script dispatched cannot. HTML already says that a label does nothing for events aimed at an interactive content descendant, such as the agecheck element itself. So a click on an agecheck element inside its label starts at most one check.

IDL attributes and methods

The age IDL attribute [=reflects=] the [^agecheck/age^] content attribute, with a default value of 18. The IDL attribute does not check for 13, 16, or 18; run a check does that. The disabled, name, and required IDL attributes [=reflect=] the content attributes of the same name.

The willValidate, validity, and validationMessage IDL attributes, and the checkValidity(), reportValidity(), and setCustomValidity(error) methods, are part of the constraint validation API. The labels IDL attribute provides a list of the element's label elements, as labels defines. The disabled, form, and name IDL attributes are part of the element's forms API. The form getter follows HTML's definition.

The constructor() follows HTML's [HTMLConstructor] rules.

Like every other HTML element interface, HTMLAgeCheckElement is exposed in every context. A page that is not a secure context gets the element too. A trusted click on it fires error, because run a check fails when the relevant settings object is not a secure context.

This form asks whether the person is 18 or older. The form submits only after a check succeeds. 

<form method="post" action="/enter">
  <agecheck name="age" age="18" required>Share that I'm 18 or older</agecheck>
  <button>Enter</button>
</form>
