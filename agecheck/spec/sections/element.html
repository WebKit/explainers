The agecheck element represents a control labeled by its contents. A person uses the control to share that they are at least the age that the [^agecheck/age^] attribute names. The element uses the HTMLAgeCheckElement interface.

The answer is an age that the person, a parent, or the platform declared. The element does not prove anyone's age. Anyone can send the same form value to a server.

The `age` attribute

The age content attribute gives the age that a check asks about. If the attribute is present, its value must be a valid non-negative integer equal to 13, 16, or 18.

To parse an age given a string or null |value|:

  1. If |value| is null, then return 18.
  2. Let |number| be the result of parsing |value| with the rules for parsing non-negative integers.
  3. If |number| is an error, then return failure.
  4. If |number| is 13, 16, or 18, then return |number|.
  5. Return failure.

The requested age of an [^agecheck^] element is the result of running [=agecheck/parse an age=] on the element's [^agecheck/age^] attribute value. When the element has no `age` attribute, [=agecheck/parse an age=] gets null instead.

The [=attribute change steps=] for an [^agecheck^] element |element|, given |localName|, |oldValue|, |value|, and |namespace|, are:

  1. If |localName| is not `age` or |namespace| is not null, then return.
  2. Let |oldAge| be the result of [=agecheck/parse an age=] given |oldValue|.
  3. Let |newAge| be the result of [=agecheck/parse an age=] given |value|.
  4. If |oldAge| and |newAge| are both failure, or are the same number, then return.
  5. Set |element|'s [=agecheck/meets age=] flag to false.

The `name`, `form`, `disabled`, and `required` attributes

Authors use the `form` attribute to associate the [^agecheck^] element with its [=button/form owner=]. The `name` attribute represents the element's name. Authors use the `disabled` attribute to make the control non-interactive and to keep its value out of form submission.

The required attribute is a boolean attribute. When the attribute is specified, the element is required.

The `meetsAge` attribute

Each [^agecheck^] element has a meets age flag, a boolean. The flag is initially false.

The meetsAge getter steps are to return [=this=]'s [=agecheck/meets age=] flag.

Activation behavior

An [^agecheck^] element |element|'s activation behavior given |event| is:

  1. If |element| is disabled, then return.
  2. If |element|'s [=Node/node document=] is not [=Document/fully active=], then return.
  3. If |event|'s {{Event/isTrusted}} attribute is false, then return.
  4. Run a check given |element|.

What counts as activating the element

The user agent must fire a `click` event at an [^agecheck^] element, with {{Event/isTrusted}} set to true, in each of these cases:

  • The person clicks or taps the element.
  • The element has focus and the person presses the Enter key, or presses and then releases the Space key. For the button role, these are the same keys that activate a `button` element on the same platform.
  • The person's assistive technology asks for the element's press action, or the platform's equivalent default action. Before the user agent fires the `click` event, it MUST give the element's [=relevant global object=] transient activation, as it does for an activation triggering input event.
  • The person clicks a `label` whose labeled control is the element. The label patch in makes that a trusted click on the element.
The rule in the last item patches HTML's user activation processing model, which has no notion of an assistive technology press action. The rule sits here for now. It moves into HTML with the other patches.

IDL attributes and methods

The age IDL attribute [=reflects=] the [^agecheck/age^] content attribute, with a default value of 18. The disabled, name, and required IDL attributes [=reflect=] the content attributes of the same name.

The willValidate, validity, and validationMessage IDL attributes, and the checkValidity(), reportValidity(), and setCustomValidity(error) methods, are part of the constraint validation API. The labels IDL attribute provides a list of the element's `label` elements, as `labels` defines. The `disabled`, form, and `name` IDL attributes are part of the element's forms API. The `form` getter follows `HTML's definition`.

The constructor() follows HTML's `[HTMLConstructor]` rules.
