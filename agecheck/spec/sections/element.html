The agecheck element represents a control labeled by its contents. A person uses the control to share their age group with the page. The page names the groups it can use in the [^agecheck/groups^] attribute. The element uses the HTMLAgeCheckElement interface.

The answer is an age group that the person, a parent, or the platform declared. The element does not prove anyone's age. Anyone can send the same form value to a server.

The `groups` attribute

The groups content attribute lists the age groups that the page can use. If the attribute is present, its value must be an unordered set of unique space-separated tokens. The allowed values are the six age group tokens in this table. Each age group has a lowest age and a top age. A top age of none means the group has no upper end.

Age group Lowest age Top age
`13+` 13 none
`16+` 16 none
`18+` 18 none
`13-15` 13 15
`13-17` 13 17
`16-17` 16 17
Every age group token begins with the group's lowest age. A page can read that age with `parseInt(element.group, 10)`.

To parse age groups given a string or null |value|:

  1. If |value| is null, then return « "18+" ».
  2. Let |tokens| be the result of [=split a string on ASCII whitespace| splitting=] |value| on ASCII whitespace.
  3. Let |groups:ordered set| be a new empty [=ordered set=].
  4. [=list/For each=] |token| of |tokens|: if |token| is the token of an [=age group=], then [=set/append=] |token| to |groups|.
  5. If |groups| is empty, then return « "18+" ».
  6. Return |groups|.

The requested groups of an [^agecheck^] element are the result of running [=agecheck/parse age groups=] on the element's [^agecheck/groups^] attribute value. When the element has no `groups` attribute, [=agecheck/parse age groups=] gets null instead.

The [=attribute change steps=] for an [^agecheck^] element |element|, given |localName|, |oldValue|, |value|, and |namespace|, are:

  1. If |localName| is not `groups` or |namespace| is not null, then return.
  2. Let |oldGroups| be the result of [=agecheck/parse age groups=] given |oldValue|.
  3. Let |newGroups| be the result of [=agecheck/parse age groups=] given |value|.
  4. If |oldGroups| and |newGroups| contain the same tokens, in any order, then return.
  5. Set |element|'s [=agecheck/shared group=] to the empty string.

The `name`, `form`, `disabled`, and `required` attributes

Authors use the `form` attribute to associate the [^agecheck^] element with its [=button/form owner=]. The `name` attribute represents the element's name. Authors use the `disabled` attribute to make the control non-interactive and to keep its value out of form submission.

The required attribute is a boolean attribute. When the attribute is specified, the element is required.

The `group` attribute

Each [^agecheck^] element has a shared group, an {{AgeGroup}} value. The value is either the empty string or the token of an [=age group=]. The empty string means the person has not shared a group. The shared group starts as the empty string.

The group getter steps are to return [=this=]'s [=agecheck/shared group=].

Activation behavior

An [^agecheck^] element |element|'s [=EventTarget/activation behavior=] given |event| is:

  1. If |element| is disabled, then return.
  2. If |element|'s [=Node/node document=] is not [=Document/fully active=], then return.
  3. If |event|'s {{Event/isTrusted}} attribute is false, then return.
  4. [=agecheck/Run a check=] given |element|.

What counts as activating the element

The user agent MUST fire a `click` event at an [^agecheck^] element, with {{Event/isTrusted}} set to true, in each of these cases:

  • The person clicks or taps the element.
  • The element has focus and the person presses the Enter key, or presses and then releases the Space key. For the button role, these are the same keys that activate a `button` element on the same platform.
  • The person's assistive technology asks for the element's press action, or the platform's equivalent default action. Before the user agent fires the `click` event, the user agent MUST give the element's [=relevant global object=] transient activation, as it does for an activation triggering input event.
  • The person clicks a `label` whose labeled control is the element. The label patch in [[[#label]]] makes that a trusted click on the element.
The rule in the third item patches HTML's user activation processing model, which has no notion of an assistive technology press action. The rule sits here for now. It moves into HTML with the other patches.

IDL attributes and methods

The groups IDL attribute [=reflects=] the [^agecheck/groups^] content attribute, as a {{DOMTokenList}}. The list shows the attribute as written, so it does not show the `18+` default. The [=Node/supported tokens=] for `groups`'s {{DOMTokenList}} are the allowed values defined in the [^agecheck/groups^] attribute and supported by the user agent. The disabled, name, and required IDL attributes [=reflect=] the content attributes of the same name.

The willValidate, validity, and validationMessage IDL attributes, and the checkValidity(), reportValidity(), and setCustomValidity(error) methods, are part of the constraint validation API. The labels IDL attribute provides a list of the element's `label` elements, as `labels` defines. The `disabled`, form, and `name` IDL attributes are part of the element's forms API. The `form` getter follows `HTML's definition`.

The constructor() follows HTML's `[HTMLConstructor]` rules.
