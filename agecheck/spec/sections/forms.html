Form mechanics and lifecycle

This section says how an agecheck element takes part in a form, and what happens to the meets age flag and to a running check when the page or the element changes.

The check dropped flag

Each agecheck element has a check dropped flag, initially false. The steps in this section set the flag to true when a running check must not succeed. Run a check sets the flag to false when a check starts. When the check ends and the flag is true, finish a check fires error and does not set the meets age flag.

A dropped check still waits for the person to finish with the prompt, unless a step below lets the user agent close the prompt. The page then learns nothing new from the timing.

Form owner

The agecheck element is a form-associated element. The element is also listed, submittable, resettable, and labelable.

HTML's rules for the form owner apply without change. An agecheck element with a form attribute uses the form element that the attribute names. Otherwise the element uses its nearest form ancestor. The user agent resets the form owner at the same times as for any other listed element. The {{HTMLAgeCheckElement/form}} getter follows the form IDL attribute rules.

Because the element is listed, the element appears in the form.elements and fieldset.elements collections.

Entry contribution

When the user agent constructs the entry list for a form, an agecheck element adds at most one entry. The agecheck entry has these parts:

  • The name is the value of the element's name attribute.
  • The value is the age that the check confirmed. The user agent writes the age in base ten ASCII digits with no leading zeros, such as "18".

The element adds the [=agecheck entry=] only when all of these are true:

  • the element's meets age flag is true;
  • the element has a name attribute whose value is not the empty string; and
  • the element is not disabled.

Otherwise the element adds nothing, the same as an unchecked checkbox.

The meets age flag is true only while the element's [=agecheck/requested age=] equals the age the check confirmed (see [[[#forms-age-change]]]). So the user agent can read the value from the requested age.

The agecheck element is never a button, so the step that skips "a button but not submitter" never skips the element. The element is also never a submit button. So requestSubmit() throws a TypeError when a page passes an agecheck element as the submitter.

HTML needs two small changes for this entry, and gives the exact words for both.

Reset

The agecheck reset algorithm is the reset algorithm for agecheck elements. HTML invokes the algorithm for each resettable element whose form owner is the form being reset, after the reset event is not canceled. Given an agecheck element element:

  1. If element's [=agecheck/check pending=] is true, set element's [=agecheck/check dropped=] flag to true.
  2. Set element's meets age flag to false.

The algorithm fires no event of its own. A dropped check fires error when the check ends. When the person answers the prompt after a reset, the user agent drops the answer.

Constraint validation

The agecheck element is submittable, so the element is a candidate for constraint validation unless a condition bars the element.

A disabled agecheck element is barred from constraint validation. HTML already says so for every disabled element, once the disabled attribute applies to agecheck (see [[[#forms-fieldset]]]). An agecheck element with a datalist ancestor is also barred, as for any submittable element.

An agecheck element is suffering from being missing when the element has a required attribute and the element's meets age flag is false.

The constraint validation members of {{HTMLAgeCheckElement}} use HTML's definitions without change:

  • {{HTMLAgeCheckElement/willValidate}}: see willValidate.
  • {{HTMLAgeCheckElement/validity}}: see validity.
  • {{HTMLAgeCheckElement/validationMessage}}: see validationMessage.
  • {{HTMLAgeCheckElement/checkValidity()}}: see checkValidity().
  • {{HTMLAgeCheckElement/reportValidity()}}: see reportValidity().
  • {{HTMLAgeCheckElement/setCustomValidity()}}: see setCustomValidity(). The method sets the element's custom validity error message.

So a form with a required agecheck element does not submit until a check succeeds, unless the form or the submitter turns validation off.

HTML needs two small changes for this rule, and gives the exact words for both.

Disabled state and fieldset

In Enabling and disabling form controls, the first case of "A form control is disabled" lists element names. The list gains agecheck:

the element is a button, agecheck, input, select, textarea, or form-associated custom element, and the disabled attribute is specified on this element (regardless of its value); or

The second case needs no change. An agecheck element inside a fieldset with a disabled attribute is disabled, unless the element is inside that fieldset's first legend child.

A disabled agecheck element:

  • starts no check, because HTML blocks queued click events on a disabled form control;
  • adds no entry to the entry list;
  • is barred from constraint validation; and
  • keeps its meets age flag. When the element becomes enabled again, the element adds its entry again.

When an element becomes disabled during a check, the check fires error when the check ends (see finish a check).

Cloning

The cloning steps for agecheck elements, given node, copy and subtree, do nothing. The copy starts with its meets age flag false and with no check in progress, whatever the state of node.

The input element copies its checkedness to a clone. The agecheck element does not copy its flag on purpose. A page cannot make a passed check by cloning an element that passed.

Insertion, removal and adoption

The agecheck element defines no HTML element insertion steps. HTML's insertion steps reset the form owner, as for every form-associated element.

The element defines no HTML element removing steps and no moving steps. Script can remove the element and put it back while a check runs, with insertBefore(), remove() followed by append(), or moveBefore(), and the check goes on. A page that reorders a list does exactly that, and the person's answer should survive it. When the check ends, the finish steps look at where the element is. They fail the check when the element is not connected, or when the element's node document is not the document where the check started.

So adopting the element into another document fails a running check, even when the other document is a same-origin iframe. DOM removes a node from its parent before the node moves to another document, but the agecheck element needs no adopting steps for this. The finish steps clear the check in progress flag on the document where the check started, not on the document where the element ends up.

Changing the form owner changes neither the meets age flag nor a running check. That holds for a change to the form attribute and for removing, inserting or moving the element. After the change, the new form submits the [=agecheck entry=]. HTML's reset the form owner steps likewise leave a checkbox's checkedness and a file input's files alone.

Changes to age

The attribute change steps for age clear the meets age flag when the requested age changes. A running check compares the requested age with its own snapshot when the check ends (see finish a check).

Back/forward cache

The user agent never restores the meets age flag after a navigation. When a document comes back from the back/forward cache, the user agent clears the flag before the pageshow event. The page can then update its own state.

In reactivate a document, a new step goes right after the step that resets form controls whose autofill field name is "off":

For each agecheck element whose node document is document, invoke the reset algorithm for that element.

The new step comes before the step that fires pageshow. The step covers elements that are not connected, since script can still hold them.

Navigation and unloading during a check

HTML's unloading document cleanup steps gain these steps, given a Document document:

  1. For each agecheck element element whose node document is document and whose [=agecheck/check pending=] is true:
    1. Set element's [=agecheck/check dropped=] flag to true.
    2. The user agent MUST close any prompt that the check shows.

Closing the prompt this way counts as the person closing the prompt without agreeing. A prompt that outlived its document would name a site the person no longer sees.

The dropped check never sets the meets age flag. The check queues an error event. The event loop runs that task only when the document is fully active again, because of the rules for a runnable task. A document that the user agent destroys never sees the event. A document that comes back from the back/forward cache sees the error event after the reactivation steps.

Enter and implicit submission

The agecheck element is never a submit button, so the element is never a form's default button. The element is also never a field that blocks implicit submission.

When an agecheck element has focus, a trusted Enter key press activates the element and so runs run a check. The element consumes that key press. Enter on a focused agecheck element never submits the form and never clicks the form's default button, because HTML's implicit submission applies only to fields that allow it.

Enter in a text field of the same form works as before. The user agent fires a click at the default button, and the form then validates its controls. A required agecheck element without a successful check stops the submission.
