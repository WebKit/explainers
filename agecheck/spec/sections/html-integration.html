Integration with HTML

The HTML Standard lists form controls by name in many places. A new form control has to join each list. This section names every place that needs a change. Each patch names the target section, quotes the current words, and gives the new words. Added words are marked as insertions.

Form categories

Target: [[[HTML#categories]]] in the forms section. Each list below is a list of element names. The patch adds [^agecheck^] to five of them.

  • Form-associated elements. Current list: "button fieldset input object output select textarea img form-associated custom elements". New list: add [^agecheck^] after `button`.
  • Listed elements. Current list: "button fieldset input object output select textarea form-associated custom elements". New list: add [^agecheck^] after `button`.
  • Submittable elements. Current list: "button input select textarea form-associated custom elements". New list: add [^agecheck^] after `button`.
  • Resettable elements. Current list: "input output select textarea form-associated custom elements". New list: add [^agecheck^] before `input`.
  • Labelable elements. Current list: "button input (if the type attribute is not in the Hidden state) meter output progress select textarea form-associated custom elements". New list: add [^agecheck^] after `button`.

Entry list

Target: constructing the entry list. The list of cases where the loop continues to the next field gains one case, after the case for an unchecked radio button. HTML also needs a definition of the element's value.

New case, after the case for an unchecked radio button:

|field| is an [^agecheck^] element whose meets age flag is false;

New definition, for the value of a field that is an [^agecheck^] element:

The value of an [^agecheck^] element is the empty string when its [=agecheck/meets age=] flag is false. Otherwise the value is its [=agecheck/requested age=], written as a valid non-negative integer with no leading zeros.

Constraint validation

Target: [[[HTML#constraints]]]. HTML needs two changes, one in the validity states and one in a note.

First, the entry for "Suffering from being missing" in [[[HTML#constraints]]] gains this case:

When an [^agecheck^] element has a `required` attribute and its [=agecheck/meets age=] flag is false.

Second, one note in HTML lists the elements that can be suffering from being missing. Current text of that note:

When a control has no value but has a required attribute (input required, textarea required); or, more complicated rules for select elements and controls in radio button groups, as specified in their sections.

New text:

When a control has no value but has a required attribute (input required, textarea required); or, more complicated rules for select elements, [^agecheck^] elements, and controls in radio button groups, as specified in their sections.

Label

Target: [[[HTML#the-label-element]]]. HTML lets each platform choose what a click on a label does. The [^agecheck^] element needs one fixed rule. Current text:

The activation behavior of a label element for events targeted at interactive content descendants of a label element, and any descendants of those interactive content descendants, must be to do nothing.

New paragraph, right after that text:

If a label element's labeled control is an [^agecheck^] element, then the label element's activation behavior, given event, must be as follows. If event's `isTrusted` attribute is true, then fire a synthetic pointer event named `click` at the labeled control, without the not trusted flag. Otherwise, do nothing.
