Automated testing

This section defines an extension module for the [[webdriver-bidi]] specification. Browsers and sites can use the module to test the agecheck element without a real person or a real age. Support for the module is OPTIONAL for a [=user agent=].

The ageCheck module

The ageCheck module contains a command that sets a virtual age source behavior. While a virtual age source behavior is set, a check talks to neither the platform nor the person. The user agent answers both the age source and the prompt from the behavior instead.

Types

ageCheck.VirtualAgeSourceAction = "meets" / "does-not-meet" / "no-age-set" / "declined" / "failed" / "wait" / "clear"

ageCheck.VirtualPromptAction = "share" / "cancel"

ageCheck.SetVirtualAgeSourceBehaviorParameters = {
  action: ageCheck.VirtualAgeSourceAction,
  ? prompt: ageCheck.VirtualPromptAction,
  ? context: browsingContext.BrowsingContext,
}

Each {^ageCheck.VirtualAgeSourceAction^} value names what ask the age source returns:

"meets"
The age source reports that the person is at least the age the check asks about.
"does-not-meet"
The age source reports that the person is younger than the age the check asks about.
"no-age-set"
The age source reports that the person has no age set.
"declined"
The age source reports that the person declined in the platform's own prompt. The check fires error and the user agent does not run its own prompt.
"failed"
The age source reports a failure.
"wait"
The age source never answers. The check stays pending, so a test can observe what happens while a check runs.
"clear"
The command removes a virtual age source behavior.

Each {^ageCheck.VirtualPromptAction^} value names what the virtual person does when the user agent's prompt appears:

"share"
The virtual person agrees to share. Where the prompt says the age cannot be shared, the virtual person closes the prompt instead.
"cancel"
The virtual person cancels the prompt.

The ageCheck.setVirtualAgeSourceBehavior command

Command Type
ageCheck.SetVirtualAgeSourceBehavior = (
  method: "ageCheck.setVirtualAgeSourceBehavior",
  params: ageCheck.SetVirtualAgeSourceBehaviorParameters
)
Return Type
ageCheck.SetVirtualAgeSourceBehaviorResult = EmptyResult

Each WebDriver [=session=] has a map of virtual age source behaviors, keyed by browsing context ID, and a default virtual age source behavior. Both start empty. A behavior is a pair of an action and a prompt action.

The [=remote end steps=] for the ageCheck.setVirtualAgeSourceBehavior command, given |session| and |command parameters|, are:

  1. Let |action| be |command parameters|["action"].
  2. Let |prompt action| be |command parameters|["prompt"] if present, and "share" otherwise.
  3. Let |context| be |command parameters|["context"] if present, and null otherwise.
  4. If |context| is not null:
    1. Let |navigable| be the result of [=trying=] to [=get a navigable=] with |context|.
    2. If |navigable| is not a [=top-level traversable=], return an [=error=] with [=error code=] [=invalid argument=].
  5. If |action| is "clear":
    1. If |context| is not null, remove the entry for |context| from |session|'s map of virtual age source behaviors.
    2. Otherwise, clear |session|'s map of virtual age source behaviors and set |session|'s default virtual age source behavior to null.
    3. Return [=success=] with data null.
  6. Let |behavior| be the pair (|action|, |prompt action|).
  7. If |context| is not null, set |session|'s map of virtual age source behaviors[|context|] to |behavior|.
  8. Otherwise, set |session|'s default virtual age source behavior to |behavior|.
  9. Return [=success=] with data null.

The command only accepts a top-level traversable because a check runs only in a top-level document.

Using the virtual behavior during a check

To get the virtual age source behavior for a {{Document}} |document|:

  1. If the user agent's webdriver-active flag is false, return null.
  2. Let |context ID| be the ID of |document|'s [=node navigable=]'s [=navigable/top-level traversable=].
  3. Let |session| be the current WebDriver [=session=].
  4. If |session|'s map of virtual age source behaviors contains |context ID|, return that entry.
  5. Return |session|'s default virtual age source behavior.

When ask the age source starts, the user agent MUST run [=get the virtual age source behavior=] for the element's node document. If the result is not null, the user agent MUST NOT contact the platform. The user agent instead returns the result that the behavior's action names in the list of actions.

When a virtual age source behavior applies to a check and the check reaches the user agent's prompt, the user agent MUST NOT show the prompt to a person. The user agent instead answers the prompt with the behavior's prompt action. The rules in prompt requirements do not apply to that answer.

With a virtual age source behavior, the outcomes are these, using the steps in run a check:

  • "meets" and "share": the element's {{HTMLAgeCheckElement/meetsAge}} becomes true and the element fires change.
  • "meets" and "cancel": the element fires error.
  • "does-not-meet", "no-age-set" or "failed", with either prompt action: the element fires error.
  • "declined": the element fires error. The prompt action is never used.
  • "wait": the element fires no event until the test changes the document, for example by removing the element.
The result names here must match the results that ask the age source defines. The two sections need one shared list.
"meets" and "does-not-meet" compare against whatever age the check asks about. A test cannot yet set a person who is 16 and then check both 13 and 18 on one page. An age range parameter, in place of these two actions, would allow such a test.
Remembered choices let a later check skip the prompt. The module does not yet say whether a check under a virtual behavior reads or writes remembered choices, or how a test clears them between tests.
The module stores behaviors on "the current WebDriver session", as the Digital Credentials API does. The module does not yet say which session applies when more than one session is active.

Testing with web-platform-tests

A check starts only from a trusted event. A test therefore starts a check with test_driver.click(element), which sends a real click through WebDriver. A call to the element's click() method dispatches an untrusted event and starts no check.

A check needs transient activation and consumes it. test_driver.click() supplies both the trusted event and the activation. test_driver.bless() supplies only the activation, so it does not start a check on its own. Tests use test_driver.bless() to show that a script click() inside a real click on something else still does nothing.

web-platform-tests has no testdriver.js wrapper for this command yet. A wrapper would follow test_driver.set_virtual_wallet_behavior() and take an action, a prompt action and an optional context.

These behaviors can be tested without the ageCheck module:

  • Parsing: the parser creates an agecheck element with its children.
  • IDL: the interface, the reflected attributes, and {{HTMLAgeCheckElement/labels}}.
  • Form association: the form attribute, the form's elements, and that the form data has no entry while {{HTMLAgeCheckElement/meetsAge}} is false.
  • required: the element is invalid and blocks submission while {{HTMLAgeCheckElement/meetsAge}} is false.
  • The untrusted case: click() and script-dispatched events fire no event, even inside test_driver.bless().
  • Spent activation: a page that spends the activation first, for example with window.open() in a mousedown listener, sees error from the next trusted click on the element.
  • Iframes: a trusted click on an element in an iframe fires error.
  • Non-secure contexts: HTMLAgeCheckElement is missing from window, and a trusted click on the element fires error.
  • Invalid age: a trusted click on an element whose age attribute has a value other than 13, 16 or 18 fires error. A missing age attribute is not invalid: the check asks about 18.

These failures happen before the check asks the age source, so no virtual behavior is needed.

The interface is not exposed in a non-secure context. The spec still has to say that the parser creates the element with its activation behavior there, so that a trusted click fires error.
